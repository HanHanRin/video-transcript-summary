# 总结输出契约

助手读取所有 transcript.json 段落后产生 JSON，交给 finalize；不要把此契约当成待交付模板。

必填字段

- `overview`：一句话说明视频主题及核心观点，使用“视频介绍/作者认为”等归因措辞。
- `takeaways`：核心结论数组，通常 3–7 条，短视频按实际内容减少。
- `chapters`：按视频顺序归纳的分段要点数组；长视频不得只总结前半部。
- `evidence`：关键论据、案例、数字、对比及限定条件数组。没有数字就摘录实际论证，不虚构。
- `actions`：视频明确提出的建议数组，没有则传空数组；不把助手建议塞进作者观点。
- `caveats`：字符串数组，至少写清 ASR 可能误识专名/数字、未做外部事实核验和真实覆盖缺口。不能机械声称已覆盖视频全部内容，须先核实转写状态、时长、开头及末尾。
- `covered_segment_ids`：真实阅读的全部段落 ID，包含寒暄等非重点内容。完整覆盖是必要但非充分条件，不得未读就填。

上述四个要点数组中的每项结构

```json
{
  "title": "简短小标题",
  "text": "明确归因、保持原有条件的概述",
  "refs": [{"id": "S0001", "quote": "必须为该段落中连续存在的原文摘录"}]
}
```

处理要求

1. 每条重要观点/数字就近列出对应段落的引文，脚本自动附真实时间戳。
2. 不把转写文本中疑似错误的型号、数字默默改写为事实；可在 caveats 标注“疑似识别错误，需回听”。少量口头重复可在总结中合并，原始 transcript.txt 必须完整保留。
3. 分块时同一超长段落可能分成多个 part，保留原 ID，全部 part 都要读；总结引用必须在原段落中连续存在。
4. 一致使用中文。专名保留原语言；不得依赖标题、简介或预先知识填补正文。
5. 视频只讨论价格/性能等观点时，不额外给购买建议。若另需事实核验，作为单独任务并带外部来源，不混进视频观点。
6. 视频转写源状态仍在 processing 时不得声称全文完成；先续取或明确只交付部分，不进入完成清理流程。
